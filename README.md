# 다빈치코드

방 코드 하나로 최대 4인이 붙는 다빈치코드. 서버도 계정도 없이 정적 파일만으로 돌아간다.

## 규칙

- 타일 **26장** — 검정 0~11, 흰색 0~11, 그리고 **검정 조커 / 흰색 조커**.
- 손패는 **작은 수 → 큰 수** 순으로 놓인다. 같은 숫자면 **검정이 왼쪽**.
- **색은 뒷면에서도 보인다.** 가려지는 것은 숫자뿐이다.
- 자기 차례에 **바닥에서 한 장 집고**(색만 보고 고른다), 상대의 덮인 타일 하나를 지목해 값을 부른다.
  - **적중** — 그 타일이 공개된다. 이어서 한 번 더 맞힐지, 멈출지 고른다.
  - **빗나감** — 집은 타일을 공개해서 손패에 넣고 차례가 끝난다.
- 바닥이 비면 집지 않고 추측한다. 빗나가면 **자기 타일 하나를 스스로 공개**한다.
- 자기 타일이 전부 공개되면 탈락. 마지막까지 숫자를 지킨 사람이 이긴다.

### 조커

조커는 숫자가 없고 **손패의 어느 자리에나** 놓을 수 있다. 한 번 놓으면 움직이지 않는다.
맞히려면 숫자가 아니라 "조커"라고 불러야 한다.

판이 시작되기 전에 **모두가 손패를 정리하는 단계**를 거친다. 이때 조커를 원하는 자리로 옮길 수 있다.
조커가 없는 사람도 같은 단계를 거치고, 손패 장수도 처음부터 같기 때문에
"저 사람이 자리를 고르고 있다 = 조커를 가졌다"가 드러나지 않는다.

조커를 지키기 위한 장치가 하나 더 있다. **집은 타일은 숫자든 조커든 항상 자리를 고르는 단계를 거친다.**
숫자 패만 자동으로 놓이면 "자리를 고르고 있다 = 조커를 들었다"가 그대로 드러나기 때문이다.
숫자 패는 순서에 맞는 자리가 밝게 표시되고, 다른 자리를 눌러도 맞는 자리로 붙는다.
밖에서 보면 두 경우가 구분되지 않는다.

## 조작

- 바닥의 타일을 눌러 한 장 집는다. 바닥은 **색끼리 묶여 정렬**되어 있다.
- 상대의 덮인 타일을 누르고 숫자(또는 조커)를 고른다.
- 놓을 자리를 고르면 손패가 벌어지며 타일이 끼어든다. 이 모션은 **모두에게 보인다**.
- `추론 보조` 를 켜면 순서상 불가능한 값이 흐려진다.

### 누가 무엇을 불렀는지

추측할 때마다 그 타일 위에 부른 값이 말풍선으로 뜬다 — 빗나가면 빨강에 타일이 흔들리고,
적중하면 초록에 타일이 부서지며 넘어간다.

그리고 **빗나간 시도는 그 칸 아래에 계속 남는다.** 실제 게임에서도 모두가 기억하는
공개 정보라서, 기억에 의존하지 않게 화면에 박아둔 것이다. 내 타일에 누가 무엇을
시도했는지도 똑같이 보인다.

## 실행

```
python3 -m http.server 8777 --directory .
```

`http://localhost:8777` — 데스크톱 Chrome 권장.

- **혼자 연습** — 봇 1~3명과. 실력 3단계.
- **방 만들기** — 4자리 코드가 나온다. 친구에게 알려주면 `참가`로 들어온다.
  방장이 봇을 채워 넣을 수도 있다.

## GitHub Pages 배포

정적 파일뿐이라 그대로 올리면 된다. Settings → Pages → Branch `main` / `(root)`.

## 통신

`vendor/peerjs.min.js` (PeerJS 1.5.4, MIT) 로 WebRTC 직접 연결을 맺는다.
방을 찾는 데만 PeerJS 공개 중계 서버를 쓰고, 그 뒤 오가는 데이터는 브라우저끼리 직접 간다.

**방장의 브라우저가 심판이다.** 규칙 판정도 방장이 하고, 참가자에게는
`viewFor()` 로 **자기가 볼 수 있는 만큼만 잘라서** 보낸다. 참가자 쪽에는 엔진도 없고
남의 숫자도 아예 전송되지 않는다. 참가자가 보낸 메시지의 신원은 무시하고
연결 자체의 신원으로 판정하므로 남의 차례를 가로챌 수 없다.

한계는 분명하다 — **방장은 모든 패를 볼 수 있다.** P2P 구조에서는 피할 수 없다.
서로 믿는 사이끼리 하는 용도다. 그리고 방장이 나가면 판이 끝난다.

끊긴 사람은 약 3초 안에 감지해서 탈락 처리하고 판을 이어간다.
(PeerJS 는 상대가 탭을 닫아도 close 이벤트를 주지 않는 경우가 많아서, 응용 계층에서
2.5초마다 생존 신호를 주고받는다.)

## 파일

| 파일 | 역할 |
|---|---|
| `rules.js` | 규칙 엔진. 순수 함수. 네트워크도 UI도 모른다 |
| `ai.js` | 봇. 보이는 정보만으로 후보를 좁힌다 |
| `net.js` | PeerJS 래퍼. 방 만들기/참가, 생존 확인 |
| `app.js` | 화면과 진행 |
| `rules.test.js` `ai.test.js` | 노드에서 도는 테스트 |

## 테스트

```
node rules.test.js
node ai.test.js
```

- 규칙 엔진 **92개** — 덱, 놓을 자리, 조커, 빗나간 시도 기록, 시작 손패 정리, 탈락/승리, 정보 은닉,
  그리고 **무작위 500판 완주**(매 수마다 타일 26장 보존 / 정렬 유지 / 탈락자에게 차례가 가지 않음 검사)
- 봇 **3개** — 핵심은 두 가지다.
  - 후보 목록이 정답을 배제한 적이 **0회** (배제하면 봇이 맞힐 수 없는 값을 부르게 된다)
  - 후보가 하나로 좁혀졌을 때 틀린 적이 **0회** (추론이 논리적으로 건전하다는 뜻)
  - 무작위 상대에게 999승 1패

## 알려진 제약

- 방장이 나가면 판이 끝난다. 방장 이전은 없다.
- 관전 모드 없음. 판이 시작되면 새로 들어올 수 없다.
